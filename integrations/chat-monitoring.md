# Assistych. Мониторинг чатов: подключение и интеграция с таск-менеджером

Версия 07.10.2026

## 1. Что делает модуль

Мониторинг чатов читает рабочие группы Telegram и MAX, в которых вы общаетесь с клиентами. Когда в группе происходит событие, требующее внимания проджекта, Assistych создаёт сигнал и передаёт его в ваше приложение. Бот в группы ничего не пишет: он только читает.

Схема работы:

```
группа с клиентом  ->  Assistych  ->  сигнал  ->  ваше приложение (задача)
                                                          |
                         отметка "в работе / решено"  <---+
```

Сигнал создаётся в четырёх случаях: клиент недоволен, клиент спрашивает про оплату, клиент просит отчёт, клиент задал вопрос и сотрудник не ответил в рабочее время. Подробности в разделе 4.

## 2. Подключение групп Telegram

Подключает группу администратор этой группы. Это сделано намеренно: иначе любой участник группы, где уже есть наш бот, мог бы забрать переписку в свой кабинет.

Шаги:

1. Откройте в кабинете Assistych страницу «Мониторинг чатов» (раздел «Магазин», карточка «Мониторинг чатов»).
2. В блоке «Добавьте бота в группу» нажмите «Добавить в группу». Откроется Telegram.
3. Выберите группу с клиентом. Бот добавится в неё и сам привяжет группу к вашему кабинету. Ссылка одна на все группы, ею можно подключать группу за группой.
4. Если бот уже находится в группе, администратор группы отправляет в неё команду из блока «Если бот уже в группе». Она выглядит так: `/connect@AssistychBot cm_<код>`. Готовую команду можно скопировать кнопкой «Скопировать команду».
5. Сделайте бота администратором группы. Все права администратора при этом можно выключить. Без статуса администратора бот может видеть только команды, а не обычные сообщения. В списке групп такой случай помечен как «видит не всё».
6. В блоке «Отметьте своих» впишите юзернеймы сотрудников агентства, по одному в строке, и нажмите «Сохранить сотрудников». Сообщения сотрудников не считаются сообщениями клиента. Тот, кто добавил бота по ссылке, уже отмечен.
7. В списке групп (вкладка «Группы») можно вписать название клиента, как оно записано в вашей таблице. Оно попадёт в сигнал в поле `client.name`.

Что видно в кабинете. Вкладка «Сигналы» показывает ленту сигналов с фильтрами «Открытые» и «Все». Вкладка «Группы» показывает список групп со статусом: «активна», «отключена» (отключили вы кнопкой «Отключить») или «бота удалили». Переписка группы открывается для чтения.

Приватность бота. Бот видит сообщения групп, в которые его добавили после того, как для него выключен режим приватности. Если в группе бот добавлен давно и сообщений не видит, удалите его и добавьте снова либо сделайте администратором.

Группы MAX. Ссылки «добавить в группу» у MAX нет. Добавьте бота в группу по имени, сделайте его администратором с правом читать все сообщения и отправьте в группу команду `/connect cm_<код>`. Отправлять должен администратор группы. Бот ничего не ответит, группа появится в списке через несколько секунд. Старую переписку MAX боту не отдаёт.

Код привязки можно сменить в кабинете. После смены старый код перестаёт привязывать новые группы, уже подключённые остаются.

## 3. Импорт истории переписки

Бот видит сообщения только с момента добавления. Более раннюю переписку можно загрузить из экспорта Telegram Desktop. Такие сообщения помечены в кабинете «из истории», а в API имеют `"source": "import"`. Сигналов по ним не создаётся.

Как выгрузить:

1. Нужна программа Telegram Desktop для компьютера. В мобильных приложениях и в версии для macOS из App Store такого экспорта нет.
2. Откройте «Настройки», затем «Продвинутые настройки», затем «Экспорт данных Telegram».
3. Оставьте включёнными только «Частные группы» и «Публичные группы». Личные чаты, чаты с ботами, каналы, информацию об аккаунте и контакты выключите. Фото, видео и файлы не нужны.
4. Выберите формат «Машиночитаемый JSON». Если нужна не вся история, задайте дату «С».
5. Нажмите «Экспортировать». Получится файл `result.json`.

Если вы недавно входили в Telegram на этом компьютере, Telegram не начнёт экспорт сразу: он предложит повторить запрос с этого же компьютера позже, обычно через сутки.

Куда загрузить. На странице «Мониторинг чатов» есть два способа.

- Одна группа: во вкладке «Группы» откройте группу и нажмите «Загрузить историю». Формат: `result.json` экспорта одного чата.
- Все группы одним файлом: блок «История до бота: все группы одним файлом», кнопка «Выбрать файл result.json». Файл читается на вашем компьютере. Личные чаты, каналы и боты никуда не отправляются: в кабинет попадают только сообщения групп, которые уже подключены к боту. Пока идёт загрузка, вкладку закрывать нельзя. Если загрузка прервалась, выберите тот же файл ещё раз: загруженные группы пропустятся, остальное догрузится.

Ограничения. Для загрузки одной группы размер файла не больше 20 МБ. Если файл больше, выгрузите историю без медиа или за период. Группа должна быть уже подключена к боту, иначе импорт вернёт ошибку `CHAT_NOT_CONNECTED`. Если файл не является JSON-экспортом Telegram Desktop, будет ошибка `BAD_FILE`. Фото, видео и файлы из экспорта не загружаются: в API у них `media.state` равен `unavailable`.

Что получится. Сообщения появятся в переписке группы и будут доступны через API. В конце загрузки отмечаются сотрудники: если больше всех в истории писали люди, не отмеченные как «наши», кабинет покажет их имена. Если это сотрудники агентства, добавьте их в список.

## 4. Сигналы

Вид сигнала передаётся в поле `signal_type`. Какие виды ловить, владелец включает в кабинете: «Мониторинг чатов», блок «Что ловить». По умолчанию включён только `negative`.

| `signal_type` | Название в кабинете | Когда создаётся | Как определяется |
|---|---|---|---|
| `negative` | Негатив | Клиент недоволен, жалуется, грозит уйти, язвит в адрес агентства | ИИ по пачке новых сообщений клиентов |
| `payment_due` | Оплата | Клиент спрашивает про счёт, сумму, срок оплаты, обещает оплатить, просит отсрочку или продление. Сообщения «оплатили», «платёжка во вложении» и пополнение кошелька Авито сигнала не дают | ИИ |
| `report_request` | Просят отчёт | Клиент просит отчёт, статистику, цифры или итоги за период | ИИ |
| `question_unanswered` | Вопрос без ответа | Клиент задал вопрос или о чём-то попросил, а сотрудник не ответил дольше N рабочих часов | Таймер, `confidence` равен `null` |

Правила:

- Пачка сообщений классифицируется после 3 минут тишины в группе или после 20 сообщений. Все виды из одной пачки определяются одним вызовом модели. Сигнал создаётся при уверенности модели не ниже 0,6.
- Для `question_unanswered` N задаётся в кабинете в поле «Сигнал через, рабочих часов» (по умолчанию 4, от 1 до 72). Рабочее время: будни с 10:00 до 19:00 по Москве. Любое сообщение сотрудника в группе после вопроса снимает ожидание.
- Пока по группе есть открытый сигнал (`new` или `in_work`), новый сигнал того же вида не создаётся. Повторы считаются в поле `repeats` открытого сигнала. Сигналы разных видов друг другу не мешают.
- Закрытый сигнал (`done` или `dismissed`) снимает это ограничение: следующий случай даст новый сигнал.

Важно. Если ваше приложение написано по версии от 28.09.2026 и не смотрит на `signal_type`, сначала научите его различать виды, а потом включайте остальные. Иначе сигнал «Оплата» придёт задачей «Негатив».

Статусы сигнала: `new` (только что создан), `in_work` (проджект взял), `done` (решено), `dismissed` (ложное срабатывание; по таким случаям мы улучшаем распознавание).

## 5. Вебхук

Адрес вашего приложения указывается в кабинете: «Мониторинг чатов», блок «Куда отправлять сигналы», поле «Адрес вашего приложения (вебхук)». Адрес должен начинаться с `http://` или `https://`, рекомендуем HTTPS. Кнопка «Проверить» отправляет на адрес тестовое событие `signal.test`.

На каждый новый сигнал Assistych отправляет `POST` с телом JSON.

Заголовки:

| Заголовок | Значение |
|---|---|
| `Content-Type` | `application/json` |
| `X-Event` | `signal.created` (или `signal.test` для проверки) |
| `X-Signature` | `sha256=<hex>`: HMAC-SHA256 от сырого тела запроса, ключ: ключ API бизнеса |

Пример тела:

```json
{
  "event": "signal.created",
  "signal_id": "b6c1a3e2-0000-0000-0000-000000000000",
  "signal_type": "negative",
  "confidence": 0.86,
  "status": "new",
  "chat": {
    "id": "5f0e0000-0000-0000-0000-000000000000",
    "platform": "telegram",
    "telegram_chat_id": -1001234567890,
    "external_chat_id": -1001234567890,
    "title": "Ромашка / Агентство"
  },
  "client": {"name": "Ромашка"},
  "text": "за что мы вообще платим",
  "reason": "клиент недоволен результатом и сомневается в оплате",
  "link": "https://t.me/c/1234567890/5531",
  "sender": {"name": "Ирина", "username": "irina_r", "is_staff": false},
  "ts": "2026-09-28T09:41:07+00:00",
  "created_at": "2026-09-28T09:44:10+00:00",
  "cabinet_url": "https://assistych.ru/ru/chat-monitor?signal=b6c1a3e2-0000-0000-0000-000000000000"
}
```

Поля:

- `link` есть только у супергрупп Telegram. У обычных групп и у всех групп MAX он равен `null`.
- `client.name` равен названию, которое вы вписали у группы в кабинете, иначе `null`.
- Для групп MAX `platform` равен `max`, поля `telegram_*` равны `null`, идентификатор группы берите из `external_chat_id`.
- Форма тела одинакова для всех видов сигналов.

Проверка подписи на Python:

```python
import hashlib, hmac

def valid(body: bytes, header: str, api_key: str) -> bool:
    expected = "sha256=" + hmac.new(api_key.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header or "")
```

Подпись считается от сырых байтов тела, поэтому читайте тело до разбора JSON.

Повторы. Ответ с кодом 2xx означает, что сигнал принят. Время ожидания ответа 10 секунд. При любом другом ответе или таймауте мы повторяем отправку через 1, 5, 15, 60 и 240 минут. После пятой неудачи сигнал в кабинете помечается «не доставлен в ваше приложение». Сам сигнал при этом остаётся доступным в API.

Идемпотентность. Повтор одного и того же сигнала возможен, если ваш сервер принял запрос, а ответ до нас не дошёл. Определяйте повтор по `signal_id`.

Как подтвердить обработку. Для приёма достаточно ответить 2xx. Для отметки о том, что проджект взял сигнал в работу или закрыл его, вызовите `PATCH /monitor/signals/{id}` (раздел 6).

Сверка на случай недоступности вебхука. Раз в 10 или 15 минут запрашивайте `GET /monitor/signals?status=new&since=<время последней сверки>` и создавайте задачи для сигналов, которых у вас ещё нет.

## 6. API

Базовый адрес: `https://assistych.ru/api/v1`.

Авторизация: заголовок `X-API-Key: <ключ API бизнеса>`. Ключ находится в кабинете: «Настройки», «Ключ API». Владелец может перевыпустить ключ, после этого старый перестанет работать, а подпись вебхука будет считаться новым ключом.

Лимит: 60 запросов в минуту на бизнес. В ответах есть заголовки `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`. При превышении возвращается `429 RATE_LIMITED` с заголовком `Retry-After`.

Формат ошибки:

```json
{"detail": {"error": {"code": "NOT_FOUND", "message": "Чат не найден"}}}
```

Методы:

| Метод и путь | Назначение | Параметры |
|---|---|---|
| `GET /monitor/chats` | Список групп бизнеса | нет |
| `GET /monitor/chats/{id}/messages` | Сообщения группы по возрастанию времени | `limit` (1-200, по умолчанию 50); `before=<id сообщения>`: страница старше; `after=<id сообщения>`: новее. Без курсора: последние сообщения |
| `GET /monitor/signals` | Список сигналов, новые сверху | `status` (через запятую, например `new,in_work`); `signal_type` (через запятую); `chat_id`; `since` (время ISO: созданные или изменённые после); `limit` (1-200); `before=<id сигнала>`: следующая страница |
| `GET /monitor/signals/{id}` | Один сигнал | нет |
| `PATCH /monitor/signals/{id}` | Отметить обработку | тело: `{"status": "new" \| "in_work" \| "done" \| "dismissed", "comment": "текст"}`; `comment` необязателен, до 2000 знаков |
| `GET /monitor/export/signals.csv` | Выгрузка сигналов в CSV | `since`, `until` (дата или время ISO, по умолчанию последние 30 дней); `signal_type`, `status` через запятую |
| `GET /monitor/export/chats.csv` | Сводка по группам за период в CSV | `since`, `until` |

Основные поля ответов.

- Группа (`items[]` в `/monitor/chats`): `id`, `platform` (`telegram` или `max`), `external_chat_id`, `telegram_chat_id` (у MAX `null`), `title`, `chat_type` (`group` или `supergroup`), `status` (`active`, `left`: бота удалили, `disabled`: отключили в кабинете), `client_name`, `bot_is_admin`, `sees_all_messages`, `open_signals`, `last_message_at`, `bound_at`.
- Сообщение: `id`, `external_message_id`, `telegram_message_id`, `sender` (`name`, `username`, `external_user_id`, `telegram_user_id`, `is_staff`), `text`, `kind` (`text`, `photo`, `voice`, `video`, `video_note`, `document`, `sticker`, `audio`, `animation`, `other`), `media`, `source` (`bot` или `import`), `sent_at`, `edited_at`, `link`. В ответе также есть `has_more`.
- Сигнал: `id`, `signal_type`, `status`, `confidence`, `text`, `reason`, `repeats`, `comment`, `chat`, `sender`, `message_id`, `link`, `ts`, `delivery` (`none`, `pending`, `sent`, `failed`), `delivery_attempts`, `delivery_error`, `created_at`, `updated_at`, `closed_at`. В списке также есть `has_more`.

Коды ошибок:

| Код | Когда |
|---|---|
| `401 API_KEY_INVALID` | неверный или отсутствующий ключ |
| `404 NOT_FOUND` | группа или сигнал не найдены либо принадлежат другому бизнесу |
| `400 INVALID_ID` | идентификатор не является корректным UUID |
| `409 OPEN_SIGNAL_EXISTS` | сигнал нельзя вернуть в `new` или `in_work`, пока по группе открыт другой сигнал того же вида |
| `422` | неверное тело запроса или параметры |
| `429 RATE_LIMITED` | превышен лимит запросов |

Примеры запросов.

Список открытых сигналов:

```
curl -H "X-API-Key: $ASSISTYCH_API_KEY" \
  "https://assistych.ru/api/v1/monitor/signals?status=new,in_work&limit=50"
```

Последние 30 сообщений группы:

```
curl -H "X-API-Key: $ASSISTYCH_API_KEY" \
  "https://assistych.ru/api/v1/monitor/chats/<chat_id>/messages?limit=30"
```

Взять сигнал в работу:

```
curl -X PATCH -H "X-API-Key: $ASSISTYCH_API_KEY" -H "Content-Type: application/json" \
  -d '{"status": "in_work"}' \
  "https://assistych.ru/api/v1/monitor/signals/<signal_id>"
```

Закрыть сигнал с комментарием:

```
curl -X PATCH -H "X-API-Key: $ASSISTYCH_API_KEY" -H "Content-Type: application/json" \
  -d '{"status": "done", "comment": "созвонились, вопрос решён"}' \
  "https://assistych.ru/api/v1/monitor/signals/<signal_id>"
```

Выгрузка CSV за сентябрь:

```
curl -H "X-API-Key: $ASSISTYCH_API_KEY" -o signals.csv \
  "https://assistych.ru/api/v1/monitor/export/signals.csv?since=2026-09-01&until=2026-10-01"
```

Файлы в сообщениях. Если в группу прислали фото, голосовое, видео или документ, у сообщения заполнено поле `media`:

```json
"media": {
  "kind": "voice",
  "state": "stored",
  "url": "/api/v1/files/monitor/2026-09/5c1e..._voice.m4a?exp=1790000000&sig=...",
  "mime": "audio/mp4", "size": 18432, "duration": 7,
  "files": [{"url": "...", "mime": "audio/mp4"}],
  "analysis": "done",
  "text": "[Голосовое: пришлите отчёт за сентябрь, пожалуйста]"
}
```

- `kind`: `photo`, `voice`, `audio`, `video_note` (кружок), `video`, `document`. Стикеры и гифки не сохраняются.
- `state`: `pending` (загружается), `stored` (файл есть, заполнен `url`), `too_large` (больше 20 МБ), `evicted` (удалён, чтобы освободить место), `quota`, `no_space`, `failed`, `expired` (удалён по сроку хранения), `unavailable` (из экспорта Telegram Desktop). Любое незнакомое значение считайте как «файла нет».
- `url` относительный к `https://assistych.ru`, подписанный и действует сутки. Нужен файл позже: запросите сообщения заново.
- `analysis` показывает разбор ИИ, если он включён в кабинете: `pending`, `done`, `failed`, `limit`, `skipped`, `too_large`, `null`. В поле `text` при `done` лежит расшифровка речи или описание фото. Этот же текст видит классификатор, поэтому голосовое «где отчёт?» даёт сигнал `report_request`.
- По умолчанию файлы хранятся 30 дней, на бизнес выделено 2 ГБ. Когда место кончается, удаляются самые старые файлы. Сообщения остаются.

Выгрузка CSV. Формат рассчитан на русский Excel: UTF-8 с BOM, разделитель `;`, время московское, не больше 20 000 строк за запрос. В Google Таблицах используйте «Файл», «Импорт», «Загрузить» и укажите разделитель «точка с запятой».

## 7. Инструкция для разработчика приложения

Техническое задание на подключение сигналов Assistych к таск-менеджеру.

1. Создайте публичный HTTPS-эндпоинт приёма вебхука, например `POST /webhooks/assistych`. Адрес укажите в кабинете Assistych (раздел 5).
2. Храните ключ API в переменной окружения `ASSISTYCH_API_KEY`. В исходный код ключ не вписывайте.
3. Читайте тело запроса как сырые байты до разбора JSON. Проверьте подпись `X-Signature` по алгоритму из раздела 5, сравнение выполняйте за постоянное время. При несовпадении подписи верните 401 и ничего не создавайте.
4. Обработайте `X-Event`: для `signal.test` верните 200 без действий, для `signal.created` создайте задачу.
5. Обеспечьте идемпотентность: если задача с таким `signal_id` уже существует, верните 200 и не создавайте вторую. Сохраняйте `signal_id` в задаче.
6. Формируйте задачу по `signal_type`. Заголовок: `Негатив: ...`, `Оплата: ...`, `Отчёт: ...`, `Ждёт ответа: ...`, дальше `client.name`, а если он пуст, `chat.title`. Для любого другого значения `signal_type` используйте заголовок `Сигнал: ...` и всё равно создайте задачу, потому что виды могут добавляться. В теле задачи укажите цитату `text`, причину `reason`, автора `sender.name`, время `ts`, ссылки `link` (может быть `null`) и `cabinet_url`.
7. Отвечайте 2xx быстро, в течение 10 секунд, а тяжёлую работу выполняйте после ответа. При других ответах Assistych повторит отправку по графику из раздела 5.
8. Возвращайте статус обработки через `PATCH /monitor/signals/{signal_id}`: `in_work`, когда проджект взял задачу; `done`, когда решено; `dismissed`, когда это ложное срабатывание. Закрывайте сигнал вместе с задачей: пока сигнал открыт, новые случаи того же вида в этой группе не создают отдельных задач. Ответ `409 OPEN_SIGNAL_EXISTS` при возврате старого сигнала означает, что по группе уже открыт новый: работайте с ним.
9. Добавьте сверку раз в 10 или 15 минут по `GET /monitor/signals?status=new&since=...` с постраничным чтением через `before=<id последнего элемента>`, пока `has_more` равно `true`.
10. По желанию показывайте в задаче 10-20 последних сообщений группы (`GET /monitor/chats/{chat.id}/messages?limit=30`) и текст `media.text` рядом с сообщением. Не сохраняйте `media.url` надолго, он действует сутки.

Соблюдайте лимит 60 запросов в минуту и при ответе 429 ждите `Retry-After` секунд. API только читает данные и отмечает статусы, писать в группы от имени Assistych через него нельзя.

## 8. Ограничения и что дальше

Сейчас поддерживаются группы Telegram и MAX. WhatsApp пока не подключён.

- Бот видит сообщения с момента добавления. Более раннюю переписку Telegram можно загрузить экспортом, у MAX такой возможности нет.
- Привязывать группу может только её администратор. Группа привязана к одному бизнесу.
- Документы (pdf, docx, xlsx) сохраняются и скачиваются, но ИИ их не разбирает.
- Файлы больше 20 МБ не сохраняются.
- Интеграции с Google Таблицами нет, есть выгрузка CSV.
- Шаблонные сообщения клиентам в группы (например, напоминание об оплате) пока не делаем: для них нужны правила от агентства.

Этап 2: подключение WhatsApp и шаблонные напоминания, когда будут согласованы правила.

## Приложение А. Пример полного цикла

1. В группе «Ромашка / Агентство» клиент Ирина пишет: «за что мы вообще платим». Бот читает сообщение.
2. Через 3 минуты тишины в группе пачка сообщений уходит на разбор. ИИ определяет недовольство, `signal_type` равен `negative`, `confidence` равен 0,86.
3. Assistych создаёт сигнал и отправляет `POST` на адрес вашего приложения с заголовками `X-Event: signal.created` и `X-Signature: sha256=...`.
4. Приложение проверяет подпись, не находит `signal_id` среди существующих задач, создаёт задачу «Негатив: Ромашка» с цитатой, причиной и ссылками, и отвечает 200.
5. Проджект открывает задачу, нажимает «Взять в работу». Приложение вызывает `PATCH /monitor/signals/{signal_id}` с телом `{"status": "in_work"}`. В кабинете Assistych сигнал получает статус «В работе».
6. Проджект связывается с клиентом и закрывает задачу. Приложение вызывает `PATCH` с телом `{"status": "done", "comment": "созвонились, вопрос решён"}`. Сигнал закрыт, следующий негатив в этой группе даст новую задачу.
7. Если на шаге 4 приложение было недоступно, Assistych повторил бы отправку через 1, 5, 15, 60 и 240 минут, а сверка по `GET /monitor/signals?status=new` подобрала бы сигнал.
